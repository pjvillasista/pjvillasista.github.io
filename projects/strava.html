Strava Run Analytics

Python Strava API Tableau

A personal training analytics tool built on my own Strava data. The Strava app shows high-level summaries — this goes deeper: second-by-second pace zones, elevation profiles, and run-over-run trends tracked across a full marathon training block.

The Challenge

Training for a marathon requires understanding more than total miles logged. The Strava mobile app shows aggregate stats, but doesn't let you drill into how pace varied across a run's elevation profile, or compare training load week-over-week at a granular level. The goal was to pull the raw data and build my own analysis layer on top of it.

The Approach

1. Strava API Integration: Authenticated with the Strava OAuth 2.0 API and pulled activity streams — the raw, second-by-second data points for every run: GPS coordinates, pace, altitude, heart rate, and cadence.

2. Python Processing: Used Python and Pandas to parse the nested JSON activity streams, compute derived fields (pace zones, elevation gain per segment, average cadence per mile), and flatten to a tabular format Tableau can consume.

3. Tableau Dashboard: Built views for: (a) overall training volume over time — weekly mileage and long run trends, (b) per-run elevation profile overlaid with pace, and (c) a map view showing GPS tracks colored by pace zone.

What I Learned

The elevation-vs-pace overlay immediately showed that my pace was inconsistent on flat sections — I was varying pace by more than expected independently of gradient. That informed adjusting training to focus on steady-state effort rather than targeting a pace number.

Technologies Used

  • Python (Pandas, Requests) — API calls and data processing
  • Strava API — second-by-second activity streams
  • Tableau — training volume, elevation, pace zone, and map visualizations
